# 风格学习提示词调整方案

适用：工作台的逐篇分析、风格卡归纳与写作调用。当前为审阅方案，未修改生产代码、现有风格卡或转写稿。

## 已核对的现状

1. 当前账号卡为 8476 字符，元数据记录 2026-08-07、gpt-5.6，正文没有当前要求的 [[来源ID]] 引用格式。它不是已经按当前提示词验证过的新卡，不能把它的全部问题归因于当前生成器。
2. 旧卡把“类型片式定性”写成公式，把“每个信息层级都需要短句吐槽”写成强制规则。这两类指令与本次用户否定的过度包装、机械插话相吻合，是可疑诱因，不是已经证明的唯一原因。
3. 当前逐篇分析、最终归纳均反复突出游戏、卖点和活动转接。推广用途应保留，但只在样本实际存在时分析，不应主导通用风格学习。
4. 当前分析已经记录有价值的段落作用和原文证据，不需要废弃这套结构。需要改的是分析重心、迁移条件与最终归纳方式。
5. 当前写作直接使用整张风格卡和原文参考；只改学习提示词不会改变已有卡，也不会改变旧稿保存的快照。

## 一、逐篇分析提示词替换稿

位置：src/lib/writer-context.ts 的 styleAnalysisInstruction()。
保留现有 JSON 字段、引句核验与段落顺序核验，不另建分析系统。以下正文替换现有分析指导，末尾继续附现有 JSON 结构说明。

完整阅读这一篇转写，提取另一位写手可以据此复现的表达方式。只输出约定 JSON，不生成新稿。区分题材、事实内容、表达目的和表达方式；不要用题材代替风格，也不要由热度推断某种写法有效。

purposes 记录这篇实际承担的表达目的，narrative.forms 记录实际讲法。两者可以组合。只有正文出现介绍商品、游戏、活动或引导参与时，才分析对应推广用途；没有出现就不补这一类分析。

structure 描述信息怎样依次交给观众：开头先交代什么、暂时不交代什么；中间如何维持理解、悬念或立场；何时转向；最后停在哪里。不把全篇压缩成“钩子—反转—金句”等通用公式。

narrative.beats 按原文顺序记录关键段落的作用及证据。purpose 写清该段相对上一段增加了什么：事件、原因、具体细节、对比、论据、人物态度、情绪或语境。认真议论、情绪停留也可能承担有效作用，不要求每句都有新事实，更不要求每段都加梗。

narrative.bridges 分析有辨识度的相邻段落如何衔接，包括因果、递进、设问解释、视角切换、态度转向、情绪延续，以及确实出现的推广转接。记录 before 和 after 原句；action 解释它承接了什么、让读者理解发生了什么变化。requires 写可迁移的材料关系，例如“前面已建立某种判断，后面有改变判断的补充信息”，不要要求新任务也出现旧文同名人物、物件或数字。

moves 优先挑选有辨识度的连续表达片段，观察句子如何连起来：长句承载哪些动作或因果，短句在哪里改变节奏；用词如何带评价，评价是否需要单独插话；比喻与具体事实有哪些对应；解释到哪里停止，把什么留给观众理解；结尾如何承接前文。没有证据的维度不必硬填。

每项 action 必须描述可观察的写法，不用“口语化、有网感、有画面感”代替分析。when 写表达作用成立所需的关系，avoid 写该写法容易失真的边界。事实、模拟心理、角色式对白与直接引语应分清，不把修辞当采访证据。

quote 必须逐字摘录连续原文，保留标点。需要跨句才能展示写法时，引用完整连续片段。before 与 after 必须按原文顺序、不重叠且靠近，不把远处两句拼成自然过渡。

不把单篇观察升级为账号通则。不推测音频停顿、镜头或配乐，不把转写错误当口头禅。limitations 仅记录影响本次风格推断的真实缺口；通用事实边界集中说明，避免在每条表达分析中重复长段提醒。

按证据选取少量关键 beats、bridges 和 moves，不凑数，不强造反转、短句、粗口、比喻或推广段。保留现有字段数量与字符上限。

## 二、最终风格卡提示词替换稿

位置：src/lib/ai.ts 的 styleCardInstruction()。

根据全部逐篇分析及已核验原文证据，生成用于指导新稿的 Markdown 风格卡。描述这个作者在不同内容中实际怎样表达。以本次原文证据为依据，不沿用旧卡未经本轮证据支持的规则。

输出结构：
1. 稳定表达习惯：跨样本复现的句子组织、用词、叙述与评价关系；每项附不同来源的证据和适用边界。
2. 不同讲法的变化：区分叙事、议论、介绍、清单等实际出现的模式，说明哪些写法随模式变化，不把它们平均成固定流程。
3. 连续表达示例：用少量有代表性的相邻原句展示推进、转折、解释、情绪停留与收尾，指出前后各承担什么作用。
4. 使用条件与覆盖限制：区分稳定倾向、条件性写法和仅见一次的现象；没有证据的内容明确留空或说明未知。

每项规律写清“实际怎样写—证据—何时适用—容易怎样模仿过头”。不要把观察频繁的现象写成每篇必须执行的命令，不规定每段必须吐槽、首句必须类型片化、每篇必须反转或固定结尾句式。

保留作者有辨识度的用词，但不要生成脱离上下文的梗词库或填空模板。引用比喻时说明旧文事实为何支持该比喻，以及新材料需要什么对应关系；不要求新稿复制原有梗、人物、物件或数字。

条件应描述关系与表达任务，不能把原作事件要素列成通用使用门槛。推广只作为原文实际存在的一类用途，不支配整张卡。

合并表达同一结论的条目。账号定位和题材覆盖简述即可，优先给连续表达与迁移条件留空间。按证据数量决定篇幅，不为完整目录扩写成报告。详细逐篇分析继续保留在现有样本缓存中。

稳定习惯需有多个独立样本依据。每条规则附 [[来源ID]]「完整quote原句」；引句仅使用提供的已核验 quote 或 before/after，不改字、不拼接。原句匹配只证明引用存在，不证明规律稳定；不得据此虚报“全部”“高频”或因果效果。

## 三、必须同步的调用与缓存调整

- 账号归纳：移除“旧卡全文作为基线”的输入；以本轮证据重新归纳。已有 writer-preference 块继续由 preserveWriterPreferences 保存。其他人工写入内容应保留旧卡历史供对照，不静默声称已经完整迁移人工编辑。
- 项目归纳：同样避免旧账号卡的强制公式盖过原作证据；保留来源分组，不把某一个账号的独有表达升级为所有来源共同规律。
- 版本：更新 STYLE_ANALYSIS_VERSION，使旧逐篇分析按新指导重新学习；独立增加最终归纳提示词版本并纳入账号与项目的 sampleHash。仅修改卡片归纳提示词时无需重跑未变化的逐篇分析。
- “重新归纳”仍可复用当前分析版本的有效缓存；旧分析版本不能因强制生成只跳过最终卡而继续复用。不要自动批量重建所有用户风格卡。
- 写作提示词：把“开头方式等只服从风格卡与代表样本”改成“以原作实际表达为依据，卡片用于定位适用习惯；卡片中的规则须结合本次材料，不能为执行规则强造比喻、短句或转折”。卡与原作冲突时，不机械执行卡片硬规则。
- 首稿区分原稿内容安排与目标作者的表达方式；用户要求保留原稿节奏时保留信息释放和段落作用，不逐句扩写。
- 新风格仅用于新稿；已有草稿续改继续使用保存的风格快照，保持现有兼容性。
- 保留原子写入、旧卡历史、hash 冲突校验、任务进度、取消与错误展示。模型失败明确失败，不用本地模板补卡。

## 四、小范围验证

先在隔离输出中用相同三篇转写、同一模型生成新卡，与旧卡对照；确认不再强制套模板，也没有丢失实际风格证据。再固定相同参考作品与写作输入，分别用旧卡、新卡生成水浒卡稿，以及一条不含反转的任务。不要在这次对照中同时更换选样算法、模型和审修轮数。

代码验证覆盖：新旧缓存版本、用户偏好保留、引句和顺序校验、旧卡失败保留、并发修改冲突、项目来源分组。提示词中出现关键词的测试不能证明文案质量；最终需要人工比较生成稿的连贯程度、过度包装、重复解释、事实增添和相似感。
