# Sites 云端主库切换

## 当前状态

正式资料仍在本机。2026-09-17 查询原 Sites 项目返回 `Sites project not found`，尚未迁移资料、修改云端运行参数或切换现有 3000 服务。

## 本地隔离开发入口

运行 `npm run dev:sandbox`，访问 `http://127.0.0.1:3002`。

- 独立资料目录 `.dev-sandbox/library`，首次打开为空库。
- 独立构建目录 `.dev-sandbox/next`，不覆盖现有服务的 `.next`。
- 显式关闭 Sites 云端存储、资料转发和能力桥凭证，不启动公网网关。
- 本机模型、CLI 等外部服务配置仍可能生效；隔离资料不等于隔离额度、浏览器登录或外部文档操作。
- 现有 3000 暂不切换，避免仍依赖本机的公开站点读到测试空库。

## 恢复 Sites 访问后的切换顺序

1. 核对原项目身份、当前发布版本、正式云库已有内容及容量限制。
2. 审核 D1/R2 存储的跨实例并发写入、删除事务和版本冲突；现有进程内锁不能自动提供跨 Worker 互斥。
3. 验证持久任务执行。当前云任务使用 Worker `waitUntil`，不能据此保证长采集、转写任务可靠完成；切换前需完成持久执行与中断恢复验证。
4. 为迁移准备可恢复备份、文件清单和校验值，暂停正式写入后导入隔离目标；不覆盖未核对的云端记录。
5. 核对文件校验值、记录数量、引用和历史版本，再把正式网站切至云库。保留原库以便回退。
6. 将默认本地开发入口切至测试资料；需要操作正式资料时使用明确区分的正式入口。修改程序仍须单独发布。

未完成上述检查时，不以关闭 `SITES_WORKSPACE_SOURCE=local` 代替迁移，否则可能直接展示空云库。
